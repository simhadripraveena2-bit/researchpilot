# Benchmark reports: G-MATCH and G-LATEST-DATES

`g-match-b0.md/.json` and `g-latest-dates-b0.md/.json` are generated by
`backend/scripts/run_benchmarks.py`. This page adds what generated reports cannot show: how
the cases were made, what failed while preparing them, coverage gaps and readiness.

## What these numbers are (and are not)

| | |
|---|---|
| Split | **B0 (development)** only. No B1, B2 or B3 exists. |
| Data | **Real** records only: arXiv API and RSS (2026-11-11 feeds), bioRxiv/medRxiv API, Crossref, plus OpenAlex / Semantic Scholar where a recording exists. No constructed or synthetic records. |
| Labels | **AI-proposed** (`ai_proposed`), from the evidence quoted in each case. They are **not gold** and await team review against the primary pages (EVALUATION_FRAMEWORK §2a). No expert has labelled anything. |
| Use | Regression tests in CI and failure analysis. **Not** calibration and **not** a release estimate. |

The 100% scores below mean the system behaves as these 95 development cases expect. Part of
that agreement comes from fixing the problems the cases found (see "Failures found and fixed").
**The scores do not estimate held-out performance.**

## Methodology

Each case runs the production code on a scratch database, from recordings only:
ingestion, followed version links, the Version Matcher, enrichment, announcement capture,
the Date Resolver, the release-type classifier, and user split plus re-match for
reversibility. G-MATCH runs every pair in both orders. An unrecorded system-of-record
request makes a case **not evaluable**; an unrecorded aggregator request is answered
"unavailable". Both are reported. Every report records the git SHA, matcher rule version,
dataset hash and recording directories.

## Failures found and fixed while preparing B0

| Found | Kind | What happened | Resolution |
|---|---|---|---|
| GD-B0-034, 035, 036 | **System bug (dates)** | Crossref day-01 print dates (1 Nov 2018, 1 Mar 2026, 1 Feb 2017) were *verified* as first public dates, although the articles went online on 19 Nov and 30 Apr. The 2017 article's record was created in July. | Nominal issue dates are stored with month precision (R1_M1A_NOTES decision 70); unit test `test_day_01_issue_dates_are_nominal`. Labels unchanged. |
| GM-B0-015, reversibility for most cases | **Harness bugs** | (a) A circuit breaker opened by an earlier case's unavailable aggregator carried into later cases, so ResNet lost Semantic Scholar evidence. (b) The reversal check assumed the second `add` performs the merge, but decisive links merge inside the first `add`. | Fresh source clients per case; the reversal check now splits the actual merge event (decision 71). |
| GM-B0-012 | **Label error** | Drafted as hep-th/9711200 ↔ ATMP DOI "decisive"; the arXiv record's DOI is the IJTP printing. | Relabelled from the record; the ATMP pair became an ambiguous case. |
| GM-B0-023 | **Label error** | Drafted as an unlinked possible match; the recorded OpenAlex work lists the copy's DOI (strong link, guideline rule 2). The matcher's merge exposed it. | Relabelled to auto-match from the evidence; no rule or threshold changed. |
| GD-B0-041, 042 | **Label error** | Expected a first-public manifestation kind while expecting no first public date. | Kind removed. |

The relabels were checked against the records, not taken from the system's output. They are
still a risk: a reviewer should check them first.

## Important false positives and false negatives

None remain on B0. Before the fixes, the dangerous failures were the three **incorrectly
verified dates** above. In matching there were no false-positive merges at any point. Both
G-MATCH "false negatives" seen during preparation were caused by the harness or by labels.

## Gaps and limitations

- **Size:** 52 pairs and 43 date cases, against B0 targets of ~100 each and release-set targets
  of ≥ 600 pairs and ≥ 500 dates. One person (an AI assistant) chose the cases, so the
  selection is biased towards evidence that is easy to record.
- **Labels are not gold:** AI-proposed, single-annotator, no agreement measured.
- **Missing or thin G-MATCH categories:** conference vs extended journal version, thesis vs
  article, same authors with a different paper (only 1 related_extends with the same authors),
  generic titles. Only 1 explicit-link pair with a different title.
- **Missing G-LATEST-DATES categories:**
  - no real **primary-vs-primary conflict** (the `conflicting` confidence class is never
    expected in B0);
  - no **corroborated** case (no recorded disjoint upstream provenance);
  - no **future dates**;
  - no **window-boundary or time-zone display** cases;
  - no OpenAlex `created_date` newly-indexed case;
  - S2-only dates appear only together with OpenAlex.
  The "conflicting" category holds the nominal-issue cases. `conflicts_detected` therefore
  measures those, not true conflict detection.
- **Policy-limited recall** (correct per policy, but less than the truth): cross-listed and
  unannounced arXiv papers stay `submission_only` and are not placed on their real
  announcement day; a journal record without a preprint link cannot find the preprint
  (GD-B0-040, IJTP 1999).
- **Aggregators:** OpenAlex's keyless budget was exhausted in this environment and S2 is
  intermittent. Most cases run with aggregators "unavailable", so strong-link (non-decisive)
  matching is barely exercised (2 pairs).
- **Recordings are a snapshot** (2026-11-11/12). Source changes appear only when cases are
  re-recorded (`--record`, B0 only).
